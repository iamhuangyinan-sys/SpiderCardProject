# 控制台命令

调试控制台在 Unity 编辑器和 Windows 测试包中可用。控制台逻辑、注册、初始化及专用调试方法仅在定义 `UNITY_EDITOR` 或 `SPIDERCARD_TEST_BUILD` 时编译。UIBinder 生成的 `.gen.cs` 保持原始生成格式，只包含绑定数据，不手动加入条件编译。弃牌堆按钮复用游戏内的展示并加入弃牌堆流程。

仅用于编辑器测试的命令，用 `#if UNITY_EDITOR` 包住命令注册、处理函数和专用业务入口。需要在 Windows 测试包中使用的命令沿用 `#if UNITY_EDITOR || SPIDERCARD_TEST_BUILD`。

## 命令

| 命令 | 作用 |
|---|---|
| `skip` | 跳过当前关卡（走正常收牌结算，然后弹选关） |
| `goto <大关>-<层>` | 保存跳关进度，重载场景后打开目标层的选关界面（仅编辑器） |
| `coin <数量>` | 增加金币（商店里也能用） |

点击控制台的 Skip 按钮可直接执行 `skip`。
在编辑器中，分别输入大关号 X 和层号 Y，再点击 Goto 按钮即可执行 `goto X-Y`。

`skip` 只在卡牌场景、有进行中的对局、且不在结算收牌时可用。
`goto` 要求已经开局，并等进关、牌桌操作和场景切换结束。从 `1-1` 开始，每层把当前可选节点里最上方的一个记为已完成，直到目标层的前一层。目标层保留所有按路线解锁的节点，供玩家手动选择。已有金币、牌组和地图保留，跳过的关卡不发奖励。目标不存在时会在 Unity Console 输出错误。
`coin` 只要求在卡牌场景（选关 / 商店 / 打牌中都行）。数量必须是正整数。

## 加牌表单

加牌使用下拉菜单选择，不再支持 `add` / `add_build` 文本命令和下划线分隔的牌定义。

| 项目 | 选项 |
|---|---|
| 花色 | 红桃、方块、黑桃、梅花 |
| 点数 | A、2～10、J、Q、K、蜘蛛、任意放下 |
| 落牌技能 | 无，以及落牌技能表中已实现的技能 |
| 翻牌技能 | 无，以及翻牌技能表中已实现的技能 |
| 属性 | 属性表中已实现的属性（包含无法删除等不在牌面显示的属性） |

技能、属性名称读取配表对应的中文文案，不随游戏语言改变。
蜘蛛表示无视点数，但仍检查花色；任意放下表示移动时不检查点数和花色。

初次打开默认一项红桃、一项 A，属性为空，两个技能为无。
点击对应的增加按钮添加一个下拉项，新增项默认选择第一个选项；点击项内删除按钮移除该项。
花色最多 4 项，点数最多 5 项，达到上限后禁用增加按钮，删除后恢复；属性项数量不限。
允许重复选择，重复项也占列表数量；提交时花色、点数和属性去重。
花色、点数和属性均可删空，表示没有对应内容；技能选择无表示没有技能。
花色、点数沿用牌定义的固定排序确定主值，不以列表中的选择顺序决定。

- **AddDrawPile**：往当前关卡发牌堆随机位置洗入一张牌。要求在卡牌场景、有进行中的对局、且不在结算收牌。
- **AddBuild**：往本局牌组加入一张牌，供后续关卡使用，并立即保存。要求在卡牌场景、且不在结算收牌；不会加入当前关卡的发牌堆。

- **AddDiscardPile**：生成一张牌，中央展示后飞入当前关卡弃牌堆，刷新数量，不随机附加沉底属性，保留表单选择的自带属性。与洗入发牌堆共用展示队列，连续添加时逐张错开。
- **AddPocket**：直接生成一张正面牌加入第一个空牌包，刷新展示，不播放动画，不触发翻牌技能。没有空位时 Log 提示“添加失败：牌包没有空位”，不创建或替换牌。

AddDiscardPile / AddPocket 是控制台测试入口，要求在卡牌场景、有进行中的对局、且不在结算收牌。AddPocket 仅检查空位，允许加入带毒属性的牌，便于测试；正常拖动入牌包的规则保持不变。两者只影响当前关卡，不修改本局牌组，不额外触发洗回。

表单属性作为牌的自带属性保留。提交和隐藏再打开控制台后保留选择，结果可在编辑器的 Unity Console 或测试包的 Player 日志查看。

## 示例

```text
skip       跳过当前关卡
goto 2-4   完成到 2-3，打开第 2 大关第 4 层的选关界面
coin 60    加 60 金币
```

创建红桃 A：保留默认表单，点击 AddDrawPile 或 AddBuild。
创建万能蜘蛛：添加四个花色项，分别选择红桃、方块、黑桃、梅花，点数选择蜘蛛，再点击添加。
