# 随机关卡试玩版

开始新游戏并确认初始牌组时生成整局地图。继续游戏使用存档中的地图快照，不重新抽取。不兼容缺少地图快照的旧存档。

选初始牌组时可以输入有符号 32 位整数种子，留空则随机生成；地图界面的复制按钮可以复制当前种子。相同种子、初始牌组数量和生成器版本才能复现同一地图；洗牌与商店商品不由地图种子控制。

## 表格

关卡节点和连线由生成器生成，无需 LevelConfig 表。首关事件 11001、Boss 事件 11002 暂时写在 LevelGenerationSettings；`LevelEventConfig` 提供事件描述，`LevelTypeConfig` 提供关卡类型配置。

## 调参入口

`Assets/Scripts/GamePlay/Level/LevelGenerationSettings.cs` 集中放置难度曲线、评分系数、接龙次数权重、商店权重及奖励参数。`LevelGenerationHelper.FillCombat` 中限定首关 12～13 列 / 3～4 槽 / 1～2 次，普通关 11～13 列 / 2～4 槽 / 2～4 次，Boss 11～12 列 / 2～3 槽 / 4～5 次，以及短列/长列轮廓范围。当前先按 7 层调参；改层数时需同步阶段划分和验证代码。

首关和 Boss 的事件保持原行为，Boss 事件自身随机牌仍然随机。普通节点无开局事件。首关偏简单，Boss 评分至少比本局最难普通关高 12。接龙目标参与评分；列数和牌包沿任意路线（包括跨商店）变化不超过 1。

地图中间层一般有 2～3 个节点。随机挑选一个保底商店层，其前一层汇合，使所有路线都获得商店选择，允许绕过商店。普通随机层以 25% 权重尝试放置商店，最多每条路线 2 个、不能连续。权重是约束前的权重，不是最终节点占比。

Boss 前一层优先以 90% 的权重尝试生成商店，依次尝试所有候选位置，并要求至少一处前置节点可以在商店与战斗之间选择。连续商店、每条路线商店次数上限等约束仍然生效，因此实际出现率低于 90%。

生成器 v2 按 UI 居中后的实际位置限制连线：相邻层最多上下偏移一个节点间距，不跨两行，也不交叉。所有节点仍保证可达；Boss 约束无解时最多进行 16 次确定性生成尝试。已有地图快照不改写，需要开始新游戏查看新连线。

金币在生成时按评分和 ±8% 浮动确定，首关保底 120，Boss 有额外奖励。快照包含逐列发牌数、目标、奖励、事件、连线、种子和生成器版本。调整参数只影响新局。

进入关卡并完成事件后才结算实际发牌配额。牌组删减导致牌不足时，优先减少深列并保存实际配额，保持原奖励。牌数足够时不会制造空列。地图随机流与牌局洗牌、商店商品随机无关，当前不保证重新进入关卡时牌序相同。

## 验证与试玩

退出 Play 模式后运行 Unity 菜单 `Tools/Validate Random Levels`：检查 1 万个种子、难度均值、事件、发牌预算、种子复现、Unity JSON 存档、Manager 路线恢复和无效存档拒绝。此检查不写玩家存档。

试玩时开始新游戏，查看节点悬浮提示中的逐列发牌、目标和金币；进入普通关和商店后分别退出再继续，检查地图/奖励不变；走到 Boss 检查事件和目标。当前 `CardsManager.isTestMode` 默认 true，编辑器里原有的跳过洗牌行为保留，评估真实难度时应关闭测试模式。

评分只用于控制生成趋势，不保证每副洗牌可解或准确预测通关率。第一轮应重点记录牌组、种子（控制台日志）、层数、目标、通关耗时和卡住原因，再调整权重。
